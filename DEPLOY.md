# Деплой свадебного сайта на Cloudflare (бесплатно)

Сайт — Cloudflare Worker + статические ассеты, база — Cloudflare D1 (SQLite на edge).
Всё укладывается в бесплатный тариф Cloudflare.

## Что уже настроено в проекте

- **Секрет сессии** генерируется автоматически и хранится в базе (`site_content → settings`) — никакого ручного секрета вводить не нужно.
- **Telegram-токен и Chat ID** вводятся через админку (`/admin/settings`), хранятся в базе. Переменные `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` в `wrangler.jsonc` — необязательный резерв (можно задать через `wrangler secret put`, тогда они приоритетнее).
- **Миграции БД** лежат в `migrations/` и применяются одной командой.

## Шаги деплоя (один раз)

### 1. Авторизоваться в Cloudflare

```bash
npx wrangler login
```

### 2. Создать базу D1

```bash
npx wrangler d1 create svadba-db
```

В ответе будет `database_id` — впишите его в `wrangler.jsonc` вместо `REPLACE_WITH_D1_ID`.

### 3. (Опционально) Создать KV для изображений

```bash
npx wrangler kv namespace create IMAGES
```

Полученный `id` впишите в `wrangler.jsonc` вместо `REPLACE_WITH_KV_ID`.
Пока KV в коде не используется — можно просто удалить блок `kv_namespaces` из конфига.

### 4. Применить миграции к продакшен-базе

```bash
npx wrangler d1 migrations apply svadba-db --remote
```

### 5. Собрать и задеплоить

```bash
npm run build
npx wrangler deploy
```

Wrangler выдаст адрес вида `https://svadba.<аккаунт>.workers.dev` — сайт готов.

## После деплоя

1. Открыть `/admin`, войти с паролем по умолчанию **`1712`**.
2. Сразу сменить пароль: **Настройки → Смена пароля** (смена пароля также разлогинивает все старые сессии).
3. Завести гостей в разделе **Гости и ответы** — каждому гостю система сгенерирует персональную ссылку `/invite/<токен>`.
4. Заполнить рассадку по столам в разделе **Рассадка**, потом включить «Показывать рассадку гостям».
5. Подключить Telegram-бота в **Настройках** (кнопка «Тест» проверяет доставку).

## Обновления сайта

Повторять только шаг 5: `npm run build && npx wrangler deploy`.
Новые миграции (если появятся в `migrations/`) — дополнительно шаг 4.

## Кастомный домен (опционально)

В облаке: Workers & Pages → svadba → Settings → Domains & Routes → Add Custom Domain.
Домен должен быть добавлен в этот аккаунт Cloudflare (NS-записи), TLS выдаётся автоматически.

## Безопасность (что уже сделано)

- Пароль админки хранится как PBKDF2-SHA256 хэш (100k итераций), не в открытом виде.
- Сессии подписаны HMAC-SHA256 секретом из базы, живут 30 дней, инвалидируются сменой пароля.
- Вход в админку ограничен: не более 5 неудачных попыток за 10 минут с одного IP (D1).
- Cookie сессии: `httpOnly`, `SameSite=Lax`, `Secure` (в проде).
- Ответы гостей: валидация полей, whitelist напитков, кулдаун 30 секунд между отправками, лимиты длин.
- Security-заголовки: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`.
- CSRF: у SvelteKit встроена проверка Origin для всех form-действий.
