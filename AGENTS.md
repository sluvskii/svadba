# Инструкция для AI-агентов и разработчиков проекта «Свадьба Алины и Камиля»

## О проекте
Свадебный веб-сайт приглашений и координации гостей для Алины и Камиля.
- **Дата свадьбы**: 17 декабря 2026 года
- **Город**: Нефтекамск
- **Банкетная площадка**: Ресторан «Тантана» (Комсомольский проспект, 33А)
- **Цель**: Предоставить гостям роскошный, стильный и понятный персональный сервис приглашений, рассадки и сбора пожеланий (RSVP), а молодожёнам — удобную панель управления без платных сторонних сервисов.

---

## Архитектура и стек технологий
- **Фреймворк**: [SvelteKit 3](https://kit.svelte.dev/) + [Svelte 5](https://svelte.dev/) (Runes: `$state`, `$derived`, `$props`).
- **Важно**: в SvelteKit 3 алиас `$lib` удалён — везде используется `#lib` (объявлен в `package.json` → `imports`). Конфиг SvelteKit живёт в `vite.config.ts` (плагин `sveltekit()`), `svelte.config.js` отсутствует.
- **Язык**: TypeScript (строгая типизация).
- **Сборщик**: Vite 8.
- **Стилизация**: Чистый CSS без лишних тяжелых фреймворков (`src/app.css` с CSS-переменными, адаптивной сеткой и типографикой).
- **Шрифты**: `@fontsource-variable/cormorant-garamond` (заголовки, дисплейные элементы) и `@fontsource-variable/manrope` (текстовый набор).
- **База данных**: **Cloudflare D1** (распределенный SQLite на edge) — полностью бесплатный уровень (до 5 ГБ, 5 млн чтений/день).
- **Хостинг / Рантайм**: Cloudflare Pages / Workers через `@sveltejs/adapter-cloudflare`.
- **Локальный рантайн**: Wrangler (`npx wrangler`) и Miniflare для эмуляции D1 локально (`.wrangler/state/v3/d1`).

## База данных: схема таблиц
1. `guests` — список гостей, токен доступа, имя, чья сторона (невеста/жених), флаги спутника (+1) и детей, персональная заметка.
2. `rsvps` — ответы на приглашение: присутствие (`yes`/`no`), имя спутника, имена детей, выбранные напитки (JSON), аллергии/пожелания по кухне, трансфер, песня для диджея, поздравление.
3. `tables` — список столов, вместимость, порядок сортировки.
4. `seats` — привязка гостя к столу.
5. `site_content` — ключ-значение для переопределения текстов (`site`) и настроек (`settings`: хэш пароля, секрет сессии, эпоха сессии, Telegram, видимость рассадки).
6. `login_attempts` — счётчик неудачных входов в админку по IP (защита от перебора пароля).

## Команды разработки
```bash
# Установка зависимостей
npm install

# Запуск локальной миграции D1
npx wrangler d1 migrations apply svadba-db --local

# Запуск сервера разработки
npm run dev

# Проверка типов Svelte и TypeScript
npm run check

# Сборка проекта для продакшена
npm run build
```

## Развертывание в Cloudflare (бесплатно)
Полная пошаговая инструкция — в [DEPLOY.md](./DEPLOY.md). Кратко:
```bash
npx wrangler login                                # авторизация
npx wrangler d1 create svadba-db                  # создать базу, id → wrangler.jsonc
npx wrangler d1 migrations apply svadba-db --remote
npm run build && npx wrangler deploy
```
После деплоя: войти в `/admin` (пароль по умолчанию `1712`), сразу сменить пароль в настройках.

## Важные правила проекта
- **Никаких фейковых данных**: списки гостей и рассадка должны отображать только реальных гостей из базы данных. Демо-приглашение `/invite/demo` существует только в памяти и в БД не пишется.
- **Безопасность**: пароль админки — PBKDF2-хэш; сессии — HMAC с секретом из базы (генерируется автоматически), живут 30 дней, инвалидируются при смене пароля (`sessionEpoch`); вход ограничен 5 неудачными попытками за 10 минут на IP (таблица `login_attempts`).
- **Отказоустойчивость**: если Telegram-бот временно недоступен, ответ гостя все равно успешно сохраняется в базе.
- **Двуязычность**: все тексты интерфейса поддерживают русский и татарский языки.
